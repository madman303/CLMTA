# ADR-001:为什么选择DuckDB + 纯 Python 数据管道？  

## 状态  
已接受（Accepted）

## 背景  
项目当前有 3 条月度序列，各 2,121 行，共 6,363 行，属于极小规模的月度时序数据。目标是在本地/免费云环境中实现可复现的数据管道，并支持 SQL 分析。

## 决策  
1. 拒绝使用 MySQL/PostgreSQL,选择 DuckDB。  
2. 拒绝使用 Airflow 等调度工具，选择 Makefile。  
3. 数据版本控制不引入 DVC，直接使用 Git + metadata.json 记录sha256.  

## 理由  
- **DuckDB**是列式存储的嵌入式数据库（像SQLite一样无需部署），但查询分析速度极快，完美契合本项目的单机分析需求。
- **Makefile**作为最古老的任务编排工具，零依赖、语义直观，非常适合月频更新的轻量级项目。
